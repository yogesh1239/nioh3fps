# Implementation notes: S1 and S2L experiment builds

The S2L addendum below supersedes the S1 notes where v8.2 changes the design. The S1 notes are retained as historical implementation decisions.

These notes record where the S1 implementation (`src/`, `tests/`, `tools/`) departs from, interprets, or adds to `docs/PLAN.md` v7.1. Where the plan was ambiguous or did not fit, the safest reading was implemented and is listed here. Section numbers refer to PLAN.md.

## Build and verification

- Toolchain: WinLibs MinGW-w64 gcc 16.2 (UCRT), `mingw32-make`. The flags are `-O2 -static`. MinHook v1.3.3 (commit 9fbd0874) is vendored in `third_party/minhook` with its BSD-2 licence.
- Outputs:
  - `build/dinput8.dll` (stripped);
  - `build/unstripped/dinput8.dll`;
  - `build/dinput8.map`;
  - `build/BUILD_ID.txt`, holding the git short hash, with `-dirty` when uncommitted;
  - `build/nioh3fps.ini`;
  - `build/nioh3fps_probe.csv`, a copy of `docs/s05/probe_targets.csv`.
- Imports (`mingw32-make imports`): KERNEL32, `api-ms-win-crt-{convert,heap,private,runtime,stdio,string,utility}` and USER32. USER32 is needed for GetAsyncKeyState and GetForegroundWindow. dbghelp is loaded dynamically, only by the dump thread. Exports are @1..@6 as in section 3, with the Dll* exports PRIVATE.
- `mingw32-make test` runs six tests:

| Test | What it checks |
|-|-|
| `test_factor` | The review7 matrix (sim7/sim7b): 16 scenarios x 7 configs x 2 modes. Also overlap, toggle and fps-mode, clamp/NaN, and the post-dip trajectory. |
| `test_unwind` | Reads the host UNWIND_INFO from `Nioh3.exe.unpacked.exe`, builds the real stubs, and calls `RtlVirtualUnwind` from every stub instruction. It cross-checks against a copy of host code that keeps the original unwind info. A negative control (an untransformed copy) must fail. |
| `test_thunk` | All three probe thunk kinds, built through the real `probe.c`. GPRs, all 16 ymm registers (256-bit), rsp, the return address and the stack above it must arrive unchanged, with call-aligned and misaligned entry rsp. Single-stepped with a VEH: `RtlVirtualUnwind` at every thunk instruction must give the caller's rip/rsp and every GPR. Also exact counts, histogram fill/overflow, and an 8-thread stress of `lock inc` and `lock cmpxchg`. |
| `test_stubs` | Runs the P1/P2 stub bytes against the exact math in section 3. P2 must leave every fps other than 120 bit-identical. |
| `test_trace` | Flight recorder: ring wrap, seqlock and CRC rejection of torn records. It also checks that `tools/trace2csv.py` produces a CSV byte-identical to the DLL's own converter. |
| `test_probecsv` | Loads `docs/s05/probe_targets.csv` against an in-memory copy of the exe's sections. 95 targets are accepted and 2 are already covered by the built-in GetFps/GetTimeStep histograms. A corrupted-row control was checked by hand: all 3 corrupted rows were skipped. |

- A smoke host (`tests/smoke_host.c`) loaded the DLL from a scratch folder. It checked proxy forwarding (`DirectInput8Create` returns S_OK), pinning, the writer thread, the log header, and the PASSIVE status after the readiness timeout. The game was never launched and nothing was copied into the game folder.

## Deviations and interpretations

1. **Hotkeys are polled by the writer thread every 10 ms**, using `GetAsyncKeyState` and only while the game window is in the foreground. They are not read at clock entry. Calling USER32 input APIs on game worker threads could turn them into GUI threads, and section 6 forbids extra work on game threads. The toggle state is still latched only at H1/H2 entry, so a tick never sees a half-applied toggle.
2. **Flight recorder size: 16384 records (2 MB plus a 4 KB header), not ~1 MB.** The ~1 MB estimate in section 6 counted only H1/H2 records. S1 also writes camera-order records (0x567070 and 0x20dda0c), xellSleep timestamps, markers and toggles. 2 MB still keeps about 30 s of history at 120 fps.
3. **xellSleep timestamp.** Section 3 calls it "optional xellSleep timestamp". The call site 0x4a538c is an indirect `call [IAT]` (6 bytes) and has no 5-byte hookable instruction of its own. So the IAT target's entry is hooked with MinHook, and the probe timestamps only calls whose return address is `base+0x4a5392`. Other callers are passed through untouched.
4. **`StartEnabled` defaults to 1 in the S1 build**, so the would-be r1/r2 are computed and logged from the start. The forced r1 = r2 = 1.0 makes this harmless. S3 must change the default back to 0, as the plan's "toggle default off" requires.
5. **New ini key: `MarkerKey=F9`.** Section 6 uses F9 markers but section 3 lists no key for them. Every key is validated; an invalid value logs a `CONFIG:` line and falls back to the default.
6. **`Enabled=0` installs nothing.** No MinHook, no stubs and no probes are installed. Only the log header and `STATUS: DISABLED BY CONFIG` are written.
7. **H2 detour forwards r8/r9 as well.** Section 3 lists rcx, rdx and rax. Forwarding all four argument registers is a superset and costs nothing.
8. **SafeMode is part of the factor config**, so `factor_update()` forces r = 1.0 and sets a flag on every tick, rather than being bypassed elsewhere. The would-be r is still computed for the log.
9. **The DLL converts the previous session's trace to CSV itself** (`nioh3fps_trace.prev.csv`) when it starts, because users may not have Python. `tools/trace2csv.py` gives the same output (enforced by `test_trace`). The collect script uses it for any `.bin` that has no CSV yet.
10. **Probe thunks are asm and register-transparent** (team-lead constraint: the entry-count targets have unknown signatures). Every thunk leaves all GPRs, xmm/ymm registers, rsp and the stack at and above the entry rsp unchanged. Only rflags changes, and it is dead across a call. None of them assumes stack alignment.
    - **Entry count (95 CSV targets and the legacy tick):** a 16-byte thunk generated per target, `F0 48 FF 05 rel32` (`lock inc qword [rip+count_i]`) then `FF 25 rel32` (`jmp qword [rip+tramp_i]`). Each `{count, tramp}` pair has its own 64-byte line. It uses no register and no stack. One shared UNWIND_INFO with no codes and no prolog (a leaf: the return address is at [rsp]) is registered with `RtlAddFunctionTable` for all of them.
    - **Return-address histograms (GetFps, GetTimeStep):** two static thunks in `probe_thunk.S`. Each does `lock inc` on its counter, then pushes rax, rcx, rdx, r8 and r9 (all in the unwind info) and reads the key from [rsp+40]. Lookup uses open addressing over a 512-entry table: a Fibonacci hash with the 64-bit multiplier and up to 32 linear probes. It claims an empty slot with `lock cmpxchg` and counts with `lock inc`; if the table is full it counts into an overflow counter. Then it pops the registers and does `jmp [rip+tramp]`, a standard epilogue. I chose this over binning by a precomputed index because real return addresses (65+ callers) are not all known statically.
    - **C thunks (camera order 0x567070 / 0x20dda0c, xellSleep):** these need QPC and a trace record. They count with `lock inc`, push rbp, rax, rcx, rdx and r8-r11, set rbp as the frame register, align rsp down to 16, save xmm0-5, call `probe_hit(ctx, ret)`, then `lea rsp,[rbp]`, pop, and `jmp [rip+tramp]`. `probe_hit` runs no AVX code, so the ymm upper halves survive. `trace_begin` clears records with explicit stores instead of CRT memset for this reason.
    - All three kinds are verified by `test_thunk` (see the table above).
11. **Probe CSV format.** `docs/s05/probe_targets.csv` has an `aob_offset` column that the task's column list did not mention. The loader finds columns by header name and checks:
    - the `aob` at `hook_rva + aob_offset`;
    - `prologue_bytes_hex` exactly at `hook_rva`;
    - that `hook_rva` is inside `.text`;
    - that `hook_rva` is not in the middle of a `.pdata` function;
    - that it does not overlap other probes or the H1/P1/H2/P2 sites.

    Rows that fail are skipped and logged with the actual bytes. Uniqueness of the AOB across the whole image is asserted by the S0.5 script, not at runtime, to keep init short. The `retaddr_hist` rows for GetFps and GetTimeStep duplicate the built-in histogram probes and are logged as "already hooked by built-in probe".
12. **Per-tick CSV and histogram CSV** (`nioh3fps_ticks.csv`, `nioh3fps_hist.csv`) are always written in the S1 probe build. In later builds only `LogLevel=Debug` writes them, as section 6 says.
    - **Ticks:** rotates to `.old` at 64 MB, measured with `_ftelli64`. That is about 20 minutes at 120 fps, so at most 128 MB on disk.
    - **Histograms:** rotates at 16 MB.
    - **Collect script:** leaves `nioh3fps_ticks.csv.old` out to keep the report zip small. It includes the current ticks file, the hist files, the log and the traces.
13. **PE timestamp mismatch is a warning, not PASSIVE.** The AOB checks (unique, at the expected RVA, exact bytes) decide, as section 3 requires. A different build that still matches is logged loudly. The in-memory SizeOfImage (0x52FB000, which includes the SteamStub `.bind` section) differs from the unpacked file (0x52C1000), so SizeOfImage is logged but never compared.
14. **Assertion dumps** (H2 called twice or more per H1 tick, or an overlap) are limited to 5 per session and at least 60 s apart, so a systematic violation cannot fill the disk. Every occurrence is still counted in the 10 s summary.
15. **The `*G` wait has its own 15-minute budget**, which starts after the byte checks pass. The clock object is created later than `.text` is decrypted, and a first launch may compile shaders for minutes; with the shared budget that ended in PASSIVE. The 120 s readiness budget (section 3) still covers decryption and the byte checks.
16. **The collect script converts traces only if `trace2csv.py` is next to it and Python is installed.** Otherwise it skips the conversion and says why, on screen and in `collect_notes.txt` inside the zip. The `.bin` files are always included, and the DLL already converts the previous session's trace by itself.

## Accepted gaps and open issues

- The MinHook relay/trampolines have no unwind info (section 3 already accepts this). A stack walk caught exactly there may be truncated. This affects diagnostics only. All probe thunks have unwind info.
- The test RNG is not Python's, so the random scenarios differ numerically from sim7.py. The asserted properties do not depend on the random values. Raw-mode error is checked exactly in double, and r is checked within float rounding because it is stored as a float.
- Not verified in the real game, because launching it was out of scope for this task:
  - readiness under SteamStub;
  - the actual hook installation;
  - hotkeys;
  - VEH minidumps;
  - the CSV probes against the decrypted in-memory image. Only the file image was checked.

  The first in-game S1 run should check that `STATUS: ACTIVE` is logged, that `PROBE CSV: 95 targets accepted, 2 already built-in, 0 skipped` is logged, and that the 10 s SUMMARY/ORDER lines are present.


## S2L addendum (v8.2, 2026-10-13)

Authority: `PLAN_v8_lockstep.md` sections 1, 2, 4 and 6, then `PLAN.md` v7.1, then the S1 decisions above. No plan file was modified. This is an offline experiment, with independent implementation review required before installation. No game process was launched and no file under SteamLibrary was written.

### Resolution and installation

- `tools/gen/gen_s2l.py`, invoked with `python -I`, derives `src/anchors.h` from the unpacked executable with pefile/Capstone. All seventeen anchors are unique in the full `.text`: GetFps, H1, expanded P1/fps/pause region, H2, P2, GetTimeStep, both camera probes, legacy tick, xell call, packet take, native pacer helper call, scene check, publisher, native frame function, the S stack builder, and the independent Sleep(1) diagnostic.
- `resolve_image()` supplies every installer target. It decodes G, the scene-manager global, the 60.0 constant, the Sleep/xell IAT operands, `help_jobs` rel32, requested/actual fps, requested/effective speed, both pause displacements, S.fps, and S.speed/S.step. S.speed/S.step are member differences derived from the three stack-builder stores and the decoded S.fps member. No fixed-RVA equality check remains in installation or CSV probe resolution. Historical RVAs are derivation/test/log hints only.
- The requested fps/P1 anchor is expanded back to the encoded `+0x618` load at 0x5ad670 and forward through both pause tests. This keeps all clock operands in one unique signature. The scene predicate is called at its uniquely resolved entry; its result is **uint8_t**, since the native false return clears AL without promising the rest of EAX.
- `.pdata` is searched for the function containing each matched P1/P2/take/Sleep site. Host extent and unwind RVA are taken from that entry. The v7 transform is retained; unsupported chained/frame-register metadata or oversized unwind info fails passive. CRCs/decoded operand values are logged from matched sites, rather than old RVAs.
- Readiness scans readable/executable `.text` until the required core resolves, with the original 120-second decryption budget. The clock object retains its separate 15-minute budget. A non-game smoke host skips the decryption wait and reports PASSIVE. A filename never authorizes a hook; only resolution does.
- P1/P2/H1/H2 are an atomic required group. A missing core prevents all installation. Missing heartbeat/helper/scene/publisher/frame disables L2 and L3; diagnostics can still run. Missing xell disables xell modes while `take` remains available. Individual probe/Sleep/xell failures have STATUS lines. `Enabled=0` still installs nothing.
- Optional CSV rows now require a unique match anywhere in `.text`, subtract their encoded AOB-to-hook offset, validate the prologue and `.pdata`, and exclude the **resolved** reserved hook ranges. The default build ships no CSV; `mingw32-make build/nioh3fps_probe.csv` explicitly builds the diagnostic file. The legacy and two camera probes are always built in.

### Heartbeat and call-site diagnostics

- The generated take stub executes the complete five-byte `mov rcx,[rsp+0x78]` at the uniquely matched gameplay heartbeat (`0x3d20eb`) using the original host RSP, calls a minimal assembly recording routine, and branches to the match-derived continuation without consuming a scratch register. Two complementary conditional branches avoid Windows' tail-jump epilogue heuristic. The generated stub has the transformed host unwind table registered with RtlAddFunctionTable.
- **Interpretation of “minimal leaf routine”:** the recording routine uses a normally callable save frame below the host RSP and directly calls QueryPerformanceCounter. It is not a strict leaf. A strict leaf with no stack changes cannot portably perform a Windows QPC call while preserving all live registers/flags and shadow space. The intercepted instruction and continuation see the original RSP. There are no C logging calls, waits, allocations or rdtsc instructions in this path. The existing game helper was avoided because it has a non-QPC fallback. This helper preserves last-error, flags, GPRs and XMM0–5; it uses no AVX instructions. Full YMM transparency is checked with a destructive fake QPC and the host's real QPC.
- `popfq` is not a canonical Windows unwind epilogue. The helper therefore has a separate PE unwind entry for each restoration instruction, describing the remaining saved frame. This is required for correct walks after RSP starts being restored, and is tested at every executed instruction. Static helper metadata belongs to the DLL; generated metadata is registered dynamically as for P1/P2.
- Native TLS uses a TlsAlloc slot below 64, read directly through the Windows x64 TEB. No GCC emutls allocation occurs on game threads. If no such slot is available, the mod stays passive. TEB offsets are Windows ABI details, not game field offsets. Value 1 means `in_gate`; value 2 marks the native H1 task until its frame continuation completes; value 3 brackets a frame reached without H1.
- The publisher detour identifies the mailbox only after a publish made by the H1 task completes and keeps the latest owned mailbox available for recovery. H1 captures the render TID from a completed raw take record for that mailbox; the assembly leaf only compares the selected pair. Unrelated pairs are recorded as hb_other and cannot advance the gate. A conflicting TID for the same mailbox invalidates health; replacement requires the explicit recovery checks below. Records capture packet=r12, mailbox=rbx and frame=r13d. Repeats compare the previous primary frame number, with pointer equality as a secondary signal; both still advance the heartbeat. Null r12 records are hb_null (flag bit 2): neither sequence nor liveness/history advances, and nulls cannot latch or qualify replacement. Relatch resets both previous frame and pointer. Repeat classification applies to the selected pair.
- The primary physical packet sequence is distinct from the selected gate sequence. In `take`, both advance together; in xell modes HB still records every physical packet take while GATE records the selected xell sequence. xell entry and exit always have separate trace records. The real C detour forwards all four arguments and the full RAX return, preserves last-error, filters the match-derived return address, and suppresses logging/publication during `in_gate`.
- **Sleep patch interpretation:** MinHook installs its five-byte branch entirely within the original six-byte indirect Sleep(1) call. The counting stub invokes the original decoded import and resumes at call+6; the untouched sixth byte is unreachable. Only that call span is patched, with MinHook's thread suspension/IP discipline. This avoids a separate unsynchronized six-byte mutation or global Sleep hook. Count and elapsed QPC time include the actual native Sleep call.

### Gate, factors and runtime invariants

- `gate.c` is a platform-free state machine. It requires a complete two-second unarmed H1 rate of 115–125/s and exact prior H1/H2 pairing. The runtime also requires two seconds of observation of the selected render pair, current heartbeat age below 100 ms, requested fps 120, clear pause bytes, a false native scene predicate, the primary clock object, and a non-null native worker context. An armed gate retains its validated native baseline because its new rate is intentionally different.
- Update TID is recaptured from each completed valid H1/H2 pair. A mismatch between the current H1 TID and the captured TID cannot wait. A changed paired TID is logged and imposes at least one second of disarm; re-arming must also satisfy the two-second native baseline. Missing/extra H2, pauses, unhealthy heartbeat and mode changes disarm/reset. Initial arming and every re-arm bootstrap by consuming the latest sequence without waiting. This can make rapid F10 re-enabling wait for another validated native window.
- The deadline is `now + min(2.5 * median(last 16 primary packet intervals), 50 ms)`, including when xell supplies the gate signal. Only `help_jobs(H1.rdx, 0)` runs during polling. Health is evaluated using a QPC read after the shared heartbeat timestamps are sampled, so an arrival during median/scene checks cannot spuriously look like a future heartbeat. QPC is read again **after** the gate for r1. Deadlines are checked between native help calls; a native job itself cannot be preempted by this mod and could overrun the nominal deadline.
- Three timeout completions in a rolling second trigger a two-second backoff and factor history reset. Five backoffs in a rolling minute disable L2/L3 for the rest of the session, with STATUS. OFF does not erase session backoff history. The next tick consumes the latest sequence; missed heartbeats are never banked.
- H1/H2 return immediately through their original trampolines during `in_gate`, before counters, pairing, TID or factor state. P1/P2 read the same native TLS slot and run their original unscaled math during re-entry; the heartbeat returns without recording. Frame/publisher/xell also suppress their task/heartbeat bookkeeping during re-entry. The vtable frame path without a preceding H1 task generates BYPASS records and a summary counter. Its H2 stays unscaled and invalidates pairing, preventing a stale H1 toggle from enabling an ungated frame. Extra or wrong-TID H2 calls likewise cannot apply r2. Overlap totals also invalidate the native pairing window; overlapping workers run the original math under the same suppression flag, and an overlap observed during polling cancels activation/reset histories after that bounded wait. This extends the S1 overlap logging to fail-passive behavior now that factors can exceed 1.
- P1/P2 apply real r1/r2 only for an armed, toggled-on Lockstep tick. SafeMode and `Lockstep=0` disable both gate and scaling. Factor reset epochs are consumed under each hook's own overlap guard; history/debt reset but cumulative loss/gain totals survive. H1 latches the common enable decision for both factors; H2 additionally requires the first paired call on that update TID. The game's native 120 Hz limiter and requested speed are untouched.
- Raw now accounts `dt - r/fps` on actual clamps and hitches, without repayment or debt. Smooth hitches also account the intentionally dropped interval. Reset/passthrough ticks and ordinary float rounding are excluded. The original factor matrix is retained; its S1 assertion that Raw loss counters are always zero is replaced with the v8 expectation that debt remains zero and accounting totals are nonnegative. Numeric trajectories are unchanged.
- Offline-only is a test procedure, not a runtime online detector, as section 6.6 requires. Tick-counting consumers remain unscaled; release is blocked pending their classification and fixes.

### Trace format and summaries

- The binary record ABI stays 128 bytes and v1. Capacity increases from 16384 to 32768 records (4 MiB plus header) because HB, two gate records and xell exit increase the event rate. Both converters accept old S1 capacities and emit byte-identical CSVs, including a legacy-sized fixture.
- HB writes a preallocated 4096-slot, 64-byte raw ring. The writer transfers completed records into the file-backed flight recorder every 50 ms; H1 independently reads the same raw ring for packet interval history. Game threads do no file I/O. An abrupt crash can lose the last writer interval of HB records; overflow is logged and gate history is conservatively revalidated. Order timing analysis by QPC, since flight-record sequence describes commit order and HB transfer is asynchronous.
- Explicit CSV columns: `hb_seq`, `hb_packet`, `hb_mailbox`, `hb_repeat`, `hb_other`, `gate_seq`, `gate_wait_us`, `gate_timeout`. In the unchanged packed ABI, HB uses frame for physical take seq, aux for packet, xell_qpc for mailbox, flags bits 0/1/2 for other/repeat/null, fps_a for packet frame number (uint32 bit pattern), and aux2 for raw-ring index. Gate uses aux for selected seq, dt for waited seconds, flags bit 0 for timeout, and aux2 for cumulative backoffs. XELL/XELL_EXIT remain distinct type codes. BYPASS records include the caller RVA.
- Ten-second GATE summaries report armed fraction, waits, mean/max elapsed wait, timeouts, backoffs, 0/1/2/3/4+ H1 ticks per primary packet heartbeat, primary heartbeat:XELL entry ratio, repeat:heartbeat ratio, hb_other, bypasses, and Sleep(1) count/elapsed ms. H1 timestamps after the gate are used for the histogram. Existing factor/order/probe summaries and the legacy rate remain.
- The flight recorder and summaries are always active. Detailed tick/histogram CSVs now follow LogLevel=Debug as v7 describes; optional CSV counters can still be collected at Info. Use Debug when collecting per-site rates for M5.

### Independent review MINOR fixes (2026-10-13)

- H1 tracks up to eight replacement (mailbox, TID) pairs in fixed storage, without locks or allocation. A candidate must belong to the latest H1-owned publish, run for at least one second at at least 20/s, and remain fresh (less than 100 ms old). The last 21 timestamps must span at most one second (20 intervals); a failed recent-rate check restarts the one-second run, so an early burst cannot mask later decay. A gap of 100 ms or more, non-increasing QPC, or raw-ring overflow also restarts qualification. Separate pairs never pool their counts. Relatching requires at least 500 ms without a take from the selected pair, independently of the configured take/xell gate signal. H1 evaluates replacement after draining a complete raw batch; a later old-pair beat in that batch vetoes replacement, and an incomplete batch cannot prove silence.
- Replacement logs `HB RELATCH` with an old-to-new arrow and both mailbox pointers/TIDs, and increments the session relatch count. It clears the median/history and previous-packet comparison, consumes the current render sequence into the gate's `last_seq`, resets factor history through the epoch, clears old heartbeat/conflict timestamps, and disarms the gate for at least one second. Existing longer backoffs and the two-second native-rate/render-observation requirements remain. Brief mixed observations during atomic scalar pair publication are covered by that hold and revalidation. The leaf has no latch CAS or recovery logic; it retains only pair comparisons, packet/repeat bookkeeping, QPC and raw recording.
- Removed `baseline_ticks == baseline_h2` and the redundant H2 accumulator. The window only accumulates ticks with exactly one preceding H2 on the paired TID; missing/extra H2 already resets it. Native rate remains the meaningful baseline check. Tests explicitly verify that both zero and two H2 calls invalidate the whole two-second window.
- Trace initialization write-touches every page (including mapped-file dirty faults), then attempts `VirtualLock` for the entire header/record mapping. Failed locking falls back to touching every page again. The existing flight-recorder initialization log reports `VirtualLock=OK/FAILED`, the error code and `prefaulted`. Successful locking keeps pages resident; the requested fallback warms pages at init but cannot guarantee residency under later memory pressure.
- The ten-second GATE summary adds `latched_mailbox`, `latched_tid`, cumulative `relatches`, and `latched_share = hb / (hb + hb_other)` (zero when no takes were recorded). The share describes selected-pair acceptance at each take during that summary window, including repeats; a window spanning replacement includes both successive selected pairs.
- The actual H1/H2 harness covers mailbox+TID replacement, TID-only replacement, mailbox-only replacement at exactly 20 Hz, the one-second hold and subsequent rearming, a live old pair, the exact 500 ms silence boundary, low rates, interrupted qualification, rate decay after an early fast run, unrelated mailbox ownership, independent candidate counts, stale batches, and old-pair activity at the end of a batch. Sleep(1) stub tests compare all 26 encoding bytes and its function table, run `RtlVirtualUnwind` at every instruction offset (0, 6, 12) against the real host's original metadata, and require untransformed metadata to fail as a negative control. Execution verifies the native call once and resumption at the original call's end, including direct resumption at stub +6 with either ZF branch. The unpacked executable is read only as a fixture; no game process is launched.

- Review-fix validation: `mingw32-make` completed with zero compiler warnings; all 11 native programs and both CSV comparisons passed (**13 PASS / 0 FAIL**). The nine assertion-counted programs report **1,937,276 checks / 0 failures**, including **8,092 integration/Sleep-stub checks** and **510 gate checks**. Only workspace artifacts were written; PLAN files and SteamLibrary were not modified.

### Gameplay xell heartbeat latch (2026-10-13)

- Reported gameplay evidence: the former take hook at `0x1a7495f` never fired (`hb=0`, mailbox remained zero), while the matched game's xellSleep caller ran about 103/s on one render TID and H1 ran 120/s. The take heartbeat now targets the gameplay path at `0x3d20eb`; the shipped ini, source template, and missing/invalid-key configuration defaults use `HeartbeatSource=take` again. See `docs/re/DECOUPLE.md` for static branch verification; no game was launched for this change.
